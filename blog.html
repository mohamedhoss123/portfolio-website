Designing VidFlow: an event-driven video pipeline

Transcoding is slow and CPU-heavy, so the API should never wait for it. VidFlow accepts an upload, returns a job id, and lets a Go worker do the heavy lifting. A Redis queue handles retries, while gRPC keeps the gateway and worker on the same typed contract.

Bounded concurrency in Go: a worker pool that behaves

Spawning one goroutine per job is easy until 400 uploads arrive at once. A fixed worker pool, a buffered jobs channel and a context make the system predictable: memory stays flat, backpressure is visible and shutdown does not leave half-written files behind.
